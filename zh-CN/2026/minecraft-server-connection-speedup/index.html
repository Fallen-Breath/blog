Minecraft 连接服务器速度优化

发表于 2026-11-15 分类于 Minecraft 阅读次数： 本文字数： 4.1k 阅读时长 ≈ 8 分钟

tl;dr，原版 Minecraft 客户端在刷新服务器列表以及连接服务器时，会被三个因素拖慢速度：

  1. 客户端每次启动后首次与任何服务器通讯前，会先向 Mojang 服务器拉取封禁服务器列表，拉取完成前阻塞后续流程。可通过 Turbo Server List 模组跳过该请求
  2. 对于纯 IP 的服务器地址，客户端在过程中会触发一次无意义的反向 DNS 解析，平白耗费数秒等待超时。可通过 Fast IP Ping 模组绕过该解析
  3. 连接开启了正版验证的服务器时，客户端与服务端均需请求 Mojang 认证服务完成会话校验，网络不畅时会在此阶段耗费大量时间甚至超时断开。可通过 Minecraft 连不上认证 Mojang 认证服务器的一种解决方案：HTTP 转发 中的方案改善连接

现象与总览

原版 Minecraft 客户端在进入多人游戏列表以及连接服务器时，经常能观察到三类卡顿现象：

  • 刚启动游戏第一次打开多人游戏界面时，列表里所有服务器都卡在 Pinging 状态，或是直接点加入服务器后一直停留在“正在连接至服务器…”界面，往往要干等很久才突然全部刷出来，连接被挂起时甚至会一直无限转圈、始终刷不出来
  • 服务器列表里的域名地址瞬间就能刷新出延迟和 MOTD，而填了 123.45.67.89:25565 或内网 IP 192.168.1.10 这类纯 IP 地址的服务器，每次刷新和连接都要固定多卡顿 1 到 5 秒
  • 点击加入正版服务器后，画面在“登录中…”或“通讯加密中…”界面停留很久才进服，严重时直接报错断开，提示无法连接到身份验证服务器或身份验证服务器处于宕机状态

这三个现象分别对应客户端从发起连接到进入服务器过程中的三个环节：拉取 Mojang 封禁服务器列表、地址解析阶段触发的反向 DNS 查询、登录阶段的正版身份验证

因素一：Mojang 封禁服务器列表拉取

机制与卡顿原因

Minecraft 在 Mojang 的 patchy 库与客户端的 AddressCheck 中内置了一套服务器黑名单检查机制。 每次客户端尝试解析服务器地址、准备发起 Ping 或建立连接时，都会调用这套机制校验目标地址是否处于封禁列表中

封禁列表的数据来自 https://sessionserver.mojang.com/blockedservers 。客户端会在首次触发地址检查时发起一次同步的 HTTP 请求去拉取这份列表：

  • 1.17 之前，拉取逻辑写在 com.mojang.patchy.BlockedServers 类的静态初始化块 <clinit> 中，Netty 的 Bootstrap 在发起连接时触发该类的加载
  • 1.17 及之后，拉取逻辑移到了 MojangBlockListSupplier#createBlockList 中，在首次访问 ServerNameResolver.DEFAULT、初始化 AddressCheck 时执行

可以看到，由于该请求与后续的网络连接是同步阻塞关系，在这次 HTTP 请求返回结果或抛出异常之前，负责 Ping 或连接服务器的线程会被完全卡死。 更糟糕的是，代码通过 URL#openConnection 获取 URLConnection 并读取数据流时，全程既没有调用 setConnectTimeout 设置连接超时，也没有调用 setReadTimeout 设置读取超时。 在 Java 标准库中，URLConnection 的这两项超时时间默认均为 0，也就是无穷大，代表永不超时。这意味着一旦请求在建立连接或读取数据时卡住，线程就会一直无限期阻塞下去，而不会在几十秒后自动超时放弃

列表只在每次启动游戏后首次打开多人游戏界面时拉取一次，后续操作会复用内存中的结果，因此服务器列表只要能被成功刷新一次，后面就不会再出现因此造成的卡顿了

国内网络环境直连 sessionserver.mojang.com 时常出现连接缓慢、丢包或连接被静默挂起的情况，这直接导致每次启动游戏后第一次打开多人游戏界面时， 所有服务器都会一起卡在“无限 Ping”的转圈状态，直到列表拉取结束或底层连接异常中断后才开始真正的服务器通讯

民间偏方：断网大法

有个这样的民间偏方，有些玄学但却非常有效：在发现服务器列表里，每个服务器都卡在 Ping 状态的，刷不出来时，就断网一下，或在 Windows 设备管理器中禁用并重新启用网络适配器，即可解决问题

结合上述机制，这一现象在技术上是完全说得通的：原版的 HTTP 请求处于同步阻塞状态，且由于超时时间默认为无穷大，直连卡住时线程根本不会自动超时，往往只能只能一直死等下去。 当手动切断网络连接时，操作系统会直接重置当前连接或向上层抛出网络不可达异常，这强制打断了正在无限等待中的网络阻塞。 而原版代码中对该请求的 IOException 做了兜底捕获，一旦抛出异常就会直接返回 null 并跳过封禁列表加载，后续的服务器 Ping 线程因此得以立刻恢复执行

解决方案：Turbo Server List

Turbo Server List 模组专门用于解决这一问题（仅在 GitHub 发布）

原版的拉取逻辑本身就对 IOException 做了兜底处理，捕获异常后会直接返回 null，等价于不启用封禁列表，从而让后续流程继续运行。 模组利用这一点，通过 Mixin 在发起网络请求前直接中断流程，彻底省去了向 Mojang 请求封禁列表的耗时，使客户端启动后首次打开服务器列表即可瞬间开始刷新

因素二：纯 IP 地址的反向 DNS 解析

机制与卡顿原因

当服务器地址填写为像 192.168.2.10:25565 这样的纯 IP 时，客户端首先调用 InetAddress.getByName(host) 创建 InetAddress 对象。 当传入参数是纯 IP 字符串时，Java 能够直接算出字节形式的 IP 地址，此时生成的 InetAddress 对象内部持有的 hostName 字段为 null

在随后的流程中，例如高版本 AddressCheck 检查封禁列表调用 ResolvedServerAddress#getHostName 时，或是在连接阶段的握手处理中，代码都会调用该 InetAddress 对象的 getHostName() 方法

一旦发现内部的 hostName 字段为 null，Java 就会向操作系统的名称服务发起一次反向 DNS 的 PTR 记录查询，试图通过 IP 反查出对应的域名。 如果最初传入的是域名，getByName 时就已经把域名填进了 hostName 字段，后续调用 getHostName() 会直接返回该字符串

绝大多数家宽公网 IP、普通云服务器 IP 以及局域网内网 IP 都没有配置反向 DNS 记录，这次反查最终只能等待 DNS 服务器返回失败或直接等待查询超时，每次都会凭空消耗 1 到 5 秒。 由于每次刷新列表和点击加入服务器都会重新构造 InetAddress 对象，这个卡顿在每次 Ping 和每次进服时都会重复发生

解决方案：Fast IP Ping

Fast IP Ping 模组针对该问题做了修复（Modrinth / CurseForge）， 该功能最早源自 TweakerMore 模组中的 yeetServerIpReversedDnsLookup 选项

模组的实现思路很直接：在客户端通过 InetAddress.getByName 解析完地址后，判断原始输入是否为纯 IP 字符串。 若是纯 IP，则调用 InetAddress.getByAddress(addr.getHostAddress(), addr.getAddress()) 重新包装出一个 InetAddress 对象，将 IP 字符串本身直接填入内部的 hostName 字段：

这样后续任何地方调用 getHostName() 时，都会直接拿到非空的 IP 字符串，从而完全绕过耗时的反向 DNS 查询

因素三：登录阶段的正版身份验证

机制与卡顿原因

当客户端与服务器建立连接后，若目标服务器开启了正版验证（online-mode=true），正式进服前就必须先完成正版身份校验：客户端需要先向 Mojang 官方认证服务登记本次进服会话，随后服务端再向 Mojang 认证服务核验该会话是否有效，两步都通过后才能进入世界

由于国内网络访问 Mojang 认证服务时常出现高延迟、丢包或连接被挂起的情况，这会直接拖慢甚至中断进服流程：

  • 卡在“登录中…”界面：通常是客户端向 Mojang 登记会话时网络不畅
  • 卡在“通讯加密中…”界面：通常是服务端向 Mojang 核验会话时网络不畅
  • 报错“暂时无法连接到身份验证服务器”或“身份验证服务器目前处于宕机状态”：通常是客户端或服务端请求 Mojang 认证服务超时失败

解决方案

关于 Mojang 认证服务连接缓慢或无法访问的问题，可参考 Minecraft 连不上认证 Mojang 认证服务器的一种解决方案：HTTP 转发 中的方案解决

总结

卡顿因素 触发时机 影响对象 解决方案
拉取 Mojang 封禁列表 每次启动游戏后首次打开列表或进服 所有服务器 Turbo Server List
纯 IP 反向 DNS 解析 每次刷新服务器列表、每次连接服务器 纯 IP 地址的服务器 Fast IP Ping
登录阶段正版身份验证 每次连接开启正版验证的服务器 开启正版验证的服务器 见 Minecraft 连不上认证 Mojang 认证服务器的一种解决方案：HTTP 转发

在客户端安装 Turbo Server List 与 Fast IP Ping，并为正版验证配好流畅的网络或转发服务后，无论是首次点开多人游戏菜单，还是日常刷新、连接服务器，都可以做到即点即刷、秒连入服
